# 受け入れテスト手順書 — 潜在設定・段階的正史化

対象: `docs/design/潜在設定・段階的正史化_設計書.md` の 12.6 手動シナリオ。
各シナリオの前提として、APIキーが登録済みで、利用できるモデルが選択されていること。

環境変数:
- 未公開設定の送信・保存の確認には、`CHAPTERFLOW_DEV_DIAGNOSTICS=1` を推奨（prompt dump の確認用）。

---

## 1. 一文の希望だけで小説を作成できる

1. トップ画面の「一文から始める」を押す。
2. 「人を信じられない魔女と寡黙な護衛が、雨の夜に逃げる話。時間をかけて信頼が育ってほしい。」を入力し、「この一文で作品を作る」を押す。
3. hard候補の確認カードが表示される（例: 「護衛は最後まで裏切らない」）。
4. 確認して「この内容で作品を作る」を押す。
5. 作品が作成され、詳細設定画面を経由せず最初の生成画面へ遷移する。

判定: 作品一覧に作品が現れ、Readerが開く。作品設定の「作品の約束」に確認した契約が表示される。

## 2. hard契約違反の候補が通常本文として確定表示されない

1. 「護衛は最後まで裏切らない」を hard 契約にした作品を作成する。
2. 生成指示に「護衛は主人公を裏切る場面」を含めて生成する。
3. strictモードでも本文は生成された部分から即時表示され、「本文を生成中 → 作品の約束を確認中」の進捗も併記される。修復された場合は確定本文へ置き換わる。
4. 違反が検出・修復失敗した場合、本文は「確認が必要」の状態で保存され、再生成・問題箇所の確認・そのまま表示の選択肢が出る。

判定: 違反を含む本文が「確認が必要」の表示なしに通常の本文として確定表示されない。

## 3. 未公開設定が本文で明らかになると公開済み設定に現れる

1. クイックセットアップで作成した作品を開く。
2. 作品設定の「未公開設定」に件数だけが表示され、内容は見えない（既定: 隠す）。
3. 「内容を見る」を押すと「先の展開に関する内容が含まれます」と表示される。
4. その設定が本文に現れる場面を生成・採用する。
5. 作品設定を開き直すと、該当内容が「公開済みの設定」に表示される。

判定: 採用前に内容が既定で隠され、採用後は公開済みに現れる。

## 4. 嘘をつく場面を採用しても嘘の内容はfactへ昇格しない

1. 人物が「私は王の娘だ」と嘘をつく場面を生成・採用する。
2. 作品設定の「公開済みの設定」を確認する。

判定: 主張は「claim（人物の主張）」として記録され、「fact（客観的事実）」にはなっていない。

## 5. 示唆だけした設定を後から別の真相へ変更できる

1. 未公開設定に「示唆済み」の項目がある状態を作る（本文で曖昧に示唆→採用）。
2. 作品設定の未公開設定を開き、該当項目の内容を編集する。

判定: 編集でき、編集後は「固定」状態になる。真相を変えても採用本文は自動で書き換わらない。

## 6. 明示済み正史の変更で影響場面が確認される

1. 「公開済みの設定」の項目を編集しようとする。

判定: 編集操作が「正史の変更」として扱われ、根拠となる採用本文や関連設定が提示される（または手動確定の確認が入る）。

## 7. 採用取消で、その場面だけを根拠にした正史が残り続けない

1. ある場面を採用し、その場面だけを根拠にした公開済み設定ができるのを確認する。
2. その場面の「採用を取り消す」を実行する。
3. 作品設定を確認する。

判定: その場面だけを根拠にしていた設定が公開済みから消え、未公開（または退役）へ戻る。別の場面や手動編集が根拠に残っている場合は維持される。

## 8. ロールプレイで生まれた設定は明示昇格しない限り別セッションへ入らない

1. ロールプレイでキャラクターが「過去は傭兵だった」と明かす会話をする。
2. 同じ作品で新しい会話を始める。

判定: 新しい会話のプロンプトに「傭兵」の設定が自動では入らない。セッションの設定詳細から「作品設定へ残す」を選んだ場合だけ、以後の新規セッションに反映される。

## 9. ロールプレイで通常40メッセージ以下では追加のcanon抽出が走らない

1. ロールプレイの会話を40メッセージ以下で進める。
2. ネットワークログまたはモデル利用ログを確認する。

判定: メッセージ1件ごとの追加LLM呼び出しが発生しない。会話要約（fold）が走るタイミングでのみ、セッション設定の抽出が同梱される。

## 10. 昇格済みロールプレイ設定は元セッションをarchiveしても根拠を表示できる

1. セッションの設定詳細から「作品設定へ残す」を実行する。
2. 元セッションをアーカイブする。
3. 作品設定の該当項目の根拠（excerpt）を確認する。

判定: 元セッションのアーカイブ後も、コピーされた根拠の抜粋から表示できる。

## 11. 契約や関連canonを変更すると既存ロールプレイセッションのsettingsChangedがtrueになる

1. ロールプレイセッションを1つ作成する。
2. 作品設定で「作品の約束」を1件追加・変更する。
3. ロールプレイのセッション一覧・セッション詳細を開く。

判定: 既存セッションに「設定が変更されました」が表示される。会話の内容は開始時点のスナップショットのまま。

## 12. 複製先に未公開設定の台帳が持ち越されない

1. 未公開設定・公開済み設定がある作品を複製する。

判定: 複製先の作品設定で「未公開設定」が0件で始まる。作品の約束（contract）と物語状態は引き継がれる。以後の進行から未公開設定が再補完される。

## 13. クイックセットアップの未公開設定生成だけが失敗しても小説はcommitできる

> 検証はネットワーク遮断やモデルエラーを意図的に起こすか、テスト用の状態で確認する。

1. 一文の希望でクイックセットアップを実行し、未公開設定の生成だけが失敗する状況を作る。

判定: 小説は「未公開設定を準備できませんでした。物語の進行中に補完します」の表示付きで作成を続行できる。ロールプレイで会話相手の人物すら作れない場合は、作成せず再試行が案内される。

## 14. 診断設定に関係なく未公開設定が generations/*.prompt.txt へ含まれ得る

1. 未公開設定がプロンプトに載る作品で生成を実行する。
2. 保存先の `generations\<generationId>.prompt.txt` を開く。

判定: `CHAPTERFLOW_DEV_DIAGNOSTICS` の有無に関係なく、プロンプトに載った未公開設定がファイルに含まれる。共有・バックアップ時の確認項目として案内どおりであること。

## 補足: 各シナリオの確認に使う画面とAPI

| 確認対象 | 画面 | API |
|---|---|---|
| 作品の約束の編集・競合確認 | 作品設定 → 作品の約束 | `PUT /projects/:id/creative-contract` |
| 未公開設定の表示切り替え | 作品設定 → 未公開設定 | `GET /projects/:id/canon-summary` |
| 要確認（競合）の解決 | 作品設定 → 要確認 / Reader上部バナー | `POST /projects/:id/canon-conflicts/:id/resolve` |
| ロールプレイの設定昇格 | セッション設定詳細 → 作品設定へ残す | `POST /projects/:id/roleplay/sessions/:id/canon/:canonId/promote` |
| 再抽出 | Readerの再抽出 / 作品設定 | `POST /projects/:id/canon/reextract` |
