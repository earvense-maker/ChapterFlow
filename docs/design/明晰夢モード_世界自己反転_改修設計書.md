# 明晰夢モード 世界・自己反転 改修設計書

- 作成日: 2026-08-20
- 状態: 草案
- 対象: 夢見るモード MVP の次期改修
- 実装後: 受け入れ完了後に `docs/design/archive/` へ移動する

## 1. 本書の位置づけ

本書は、既存の [夢見るモード MVP 設計書](夢見るモード_MVP設計書.md) で実装した体験を、明晰夢を中心とする体験へ改修するための差分設計である。

既存設計のうち、セッション保存、SSE、入力記録、夢をまたぐ生記憶、再送・復旧、プロンプト予算などの基盤は維持する。本書は主に次を置き換える。

- 体験の目的
- 世界とユーザーの関係
- 夢専用プロンプトの生成原則
- 空入力時の意味
- ユーザー向けの名称と文言

本書と既存設計が競合する場合、体験・プロンプト・UI 文言については本書を優先し、データ契約・保存・復旧については既存設計を優先する。

内部識別子 `experienceMode: 'dream'`、`sessionMode: 'dream'`、`DreamTraceEvent` 等は互換性のため変更しない。ユーザー向け名称だけを「明晰夢モード」とする案を仮採用する。

## 2. 背景と問題

夢見るモード MVP は、本文と入力欄だけの低刺激な画面、空 Enter による観察、説明のない残響によって、眠気を誘う独特の体験を成立させた。

一方で、次の問題が確認された。

1. 「夢」という語に引かれ、情景を意図的にぼんやりさせすぎる。
2. 抽象的な比喩や理由のない不連続が重なり、空間や変化を追いにくい。
3. 世界がユーザーの入力を待つ受動的な背景になりやすい。
4. ユーザーの入力が雰囲気へ吸収され、入力前後の差や因果が弱い。
5. 世界側から話しかける、触れる、連れていこうとするなどの働きかけが少ない。
6. 世界がユーザーへ関心を持ち、理解を試み、誤解を修正する関係が育ちにくい。

本改修では意識を低下させることを目標にしない。静かな画面と自由入力は残しつつ、世界の輪郭、ユーザーの判断力、世界側の自律性を強める。

## 3. 中心仮説

本モードの中心仮説を次のように定める。

> ユーザーは完成した自己として外部世界へ入るのではない。世界の断片と出会うことで、その場での自己を組み直す。世界もまた、ユーザーとの接触によって自分の形を知り、変化する。

夢らしさは、低解像度な描写や無秩序から作らない。次から作る。

- 世界と自己の境界が固定されていないこと
- 言葉、注意、接触によって所有や役割が移動すること
- 世界がユーザーを自分の一部かもしれないものとして認識すること
- ユーザーも世界との関係から一時的な自己を組み直すこと
- それでも世界に、意識的な自我では制御できない他者性が残ること

この形而上学を本文中で説明してはならない。ユーザーは、世界の振る舞いと具体的な変化から間接的に体験する。

## 4. 用語

### 4.1 明晰さ

ユーザーの意識と、現在の情景の輪郭が保たれている状態。すべての意味が説明されていることではない。

### 4.2 世界

単なる背景ではなく、人物、生き物、物、場所、現象を通じて自律的に動く分散した主体。単一の人格や語り手に限定しない。

### 4.3 自己の断片

世界とユーザーのどちらに属するかが揺らぎうる具体的な要素。例えば、名前、声、影、手、視線、記憶、時間感覚、帰る場所、誰かを待つ状態など。

「寂しがり」「承認欲求」のような心理特性は断片として扱わない。

### 4.4 働きかける存在

そのセッションでユーザーへ関心を向け、自分から接触する人物、生き物、物、場所、現象。通常の会話キャラクターに限らない。

### 4.5 仮説

働きかける存在が、現在のユーザーの言葉、沈黙、視線、接近、離脱などから持つ暫定的な理解。事実や診断ではなく、誤解と修正が可能なもの。

### 4.6 他者性

世界が自己の内面でありながら、意識的な自我の所有物や命令対象ではない性質。世界の一部は最後まで、自己か他者か確定しなくてよい。

## 5. 体験原則

### 5.1 高解像度で可塑的な世界

- 空間の位置関係、距離、材質、光、音、接触を必要な範囲で具体的に書く。
- 直前の空間・物・人物から 2〜3 個の錨を維持する。
- 何があり、入力や働きかけの前後で何が変わったかを追えるようにする。
- 非現実的な変化にも、ユーザーの言葉・注意・行動または世界側の明確な行動という、感じ取れるきっかけを持たせる。
- 意味は未確定でよいが、現象そのものは曖昧にしない。

### 5.2 世界は入力待ちの背景ではない

世界は、ユーザーの入力を受けてからだけ動く存在ではない。人物、生き物、場所、物、現象は、適度な頻度で次のような行動を自発的に起こせる。

- 話しかける、名前を呼ぶ、問いかける
- 近づく、視線を合わせる、追う、待つ
- 触れる、物を渡す、袖や手を引く
- 道を開く、塞ぐ、距離や配置を変える
- ユーザーの言葉や動きを模倣する
- 守る、隠す、誤魔化す、警戒する
- ユーザーを何かと取り違える

働きかけを毎ターン義務化してはならない。接触と静かな観察の間に呼吸を作る。ただし、長時間にわたって世界が完全に入力待ちにならないようにする。

### 5.3 世界はユーザーを理解しようとする

働きかける存在は、現在のセッション内で観測できた反応から、ユーザーが何者で、何をしているのかについて仮説を持ってよい。

仮説は次の循環で扱う。

1. 世界が現在の反応から仮説を持つ。
2. 話しかける、触れる、見せる、試すなどによって確かめる。
3. ユーザーが応答、拒絶、沈黙、離脱する。
4. 世界が仮説や接し方を維持・修正・放棄する。
5. 変化が会話だけでなく、関係、物、場所、法則のいずれかへ具体的に残る。

世界はユーザーを正しく見抜く権威ではない。誤解でき、ユーザーの反応を受けて考え直せる存在として描く。

### 5.4 世界と自己の反転

世界はユーザーの内面を象徴として解説しない。代わりに、自己の断片の所属が揺らぐ現象を起こす。

代表的な現象は次の通り。

- **主張**: 世界の存在が、ユーザーの名前、声、影などを自分のものだと主張する。
- **誤認**: ユーザーの一部分だけを、別の人物や場所として認識する。
- **移動**: 声、影、記憶、時間感覚などが世界とユーザーの間を移る。
- **共有**: 同じ名前、傷、音、記憶などが双方に同時に存在する。
- **反転**: ユーザーが世界を観察していたはずが、場所や物の側がユーザーを観察していたと分かる。
- **具現化**: ユーザーが否定・肯定・沈黙したことが、物や空間の状態として残る。
- **分裂**: 互いに矛盾する複数の存在が、それぞれ異なるユーザー像を持つ。

一回の応答で複数を詰め込まない。一つの断片を、接触、反応、変容の順で数ターンかけて扱う。

### 5.5 他者性を残す

「世界はすべてユーザーの内面である」を、「世界はユーザーが自由に所有・操作できる」と解釈してはならない。

- 世界の存在は独自の欲求、知識、誤解、抵抗を持てる。
- すべての物や人物を、ユーザーの心理を表す記号へ還元しない。
- 何が自己で何が他者かを最後に説明しない。
- ユーザーが拒絶しても、世界の存在が即座に消滅・服従する必要はない。
- 世界とユーザーの理解が一致しないまま、関係だけが変わってもよい。

### 5.6 静けさは受動性ではない

静かなターンでも、認識、関係、配置のいずれかは少し前へ進める。刺激の強さや事件数を増やすことを面白さとしない。

## 6. 基本体験ループ

体験は次の段階を持つ。ただし、固定ターン数のステートマシンとしてユーザーに見せず、場面に応じて前後してよい。

1. **定位**: 鮮明な場所、物、距離を示す。
2. **視線**: 世界のどこかがユーザーを認識している兆しを置く。
3. **接触**: 世界側から発話、接近、接触、空間変化を起こす。
4. **仮説**: 世界の存在が、ユーザーを何かとして暫定的に扱う。
5. **応答**: ユーザーの言葉、沈黙、拒絶、接近を受ける。
6. **修正**: 世界の理解や接し方が変わる。
7. **反転**: 自己の断片の所属や、観察する側・される側が揺らぐ。
8. **痕跡**: 変化を物、空間、呼び名、関係のいずれかへ残す。
9. **余韻**: 新しい謎を増やさず、変化した世界を静かに見せる。

各セッションで全段階を完遂する必要はない。ユーザーは途中で目覚められ、未完の関係も将来の残響になりうる。

### 6.1 体験例

最初の応答:

> ホームは白いタイルで囲まれ、線路は一組だけ海へ向かって伸びている。ベンチに座っていた少年が顔を上げ、あなたを「冬子」と呼ぶ。返事を待たずに近づくと、左手首をつかみ、ホームの端まで二歩だけ引く。三歩目の前で立ち止まり、確かめるようにあなたの顔を見る。「違うの？」

ユーザー入力:

> 私は冬子じゃない

次の応答:

> 少年はすぐには手を離さない。代わりに親指で手首の内側を一度なぞり、そこに何も書かれていないことを確かめる。「じゃあ、消されたんだ」先ほどまで親しげだった声に、少しだけ警戒が混じる。彼が手を放すと、足元の白いタイルに、あなたが書いた文字と同じ形で「冬子じゃない」と浮かび上がる。

この例では、次が一つの往復で起きている。

- 場所と位置関係が具体的である。
- 世界側が先に認識、発話、接触、短い移動を行う。
- 少年はユーザーを誤認し、入力を受けて仮説と接し方を変える。
- ユーザーの否定が、タイルという世界側の物へ痕跡として移る。
- 少年の新しい解釈も正解とは限らず、他者性が残る。
- ユーザーが三歩目を進むか、少年を信じるかは書かれていない。

## 7. ユーザーの主権と世界側の行動範囲

世界が自律して働きかけるには、ユーザーの行動をある程度受け身に変化させる描写を許す必要がある。一方、重要な決断や内面まで代行すると、明晰さと主権が失われる。

### 許可する

- 名前を呼ばれる、話しかけられる、質問される。
- 視線を向けられる、近づかれる、追われる。
- 手、腕、肩、衣服などへ場面相応の接触を受ける。
- 袖や手を引かれ、一歩から数歩ぶん位置を動かされる。
- 物を持たされる、道を塞がれる、扉を閉じられる。
- 世界側の行動によって、周囲の配置や感覚が変わる。

### 許可しない

- ユーザーが相手を信じた、愛した、許したと確定する。
- ユーザー自身の台詞を勝手に作る。
- 短い外力の範囲を超えて、長距離を自発的についていったことにする。
- 重大な契約、服従、告白、攻撃などをユーザーが選んだことにする。
- 拒絶や沈黙を、恐怖、嫌悪、欲望など一つの心理へ断定する。
- 作品の NG 設定や現在の明示的な境界を、世界の自律性を理由に越える。

外力で位置を動かす場合も、次の重要な応答点より前で止める。例えば「手を引かれて二歩進み、三歩目の前で相手が振り返る」とし、その後まで代行しない。

## 8. 問いかけの扱い

既存設計の「ユーザーへの質問を出さない」は、次のように分解して置き換える。

### 禁止する質問

- 「次にどうしますか」
- 「どちらを選びますか」
- 「何を調べますか」
- AI、語り手、ゲームマスターとしての進行確認
- 回答を得るまで同じ内容を繰り返す質問

### 許可する質問

- 作中の存在が、自分の事情、知識、誤解、欲求から自然に発する問い。
- ユーザーを理解しようとする暫定的な問い。
- 答えがなくても、存在が自分なりの次の行動を取れる問い。

一ターンに複数の質問を重ねず、尋問にしない。沈黙を回答の催促へ変えない。

## 9. 空 Enter の意味

UI 操作は変更せず、空 Enter は `inputKind: 'observe'` のままとする。ただし意味を、「ぼんやり時間を流す」から「自分から動かず、世界の出方を観察する」へ変更する。

`observe` に対する応答は、次のいずれかを行う。

- 見落としていた具体的な情報を明らかにする。
- ユーザーを観察していた存在が動き出す。
- 世界側が沈黙を受け、自分から話す・近づく・離れる。
- 場所や物が小さな決断をして状態を変える。
- 何も大きく起こらない時間の中で、対象の輪郭や関係を鮮明にする。

毎回事件を起こす必要はない。ただし、連続する `observe` をすべて無変化や抽象的な余韻だけで返さない。

## 10. 過去の生記憶と残響

既存の `DreamTraceEvent` は、ユーザーの性格や嗜好ではなく、生の言葉、観察、目覚めを保存する契約のまま維持する。

本改修では、選ばれた過去の残響を「ユーザー理解の根拠」ではなく、「すでに世界側へ散らばっていた断片」の材料として使える。

例:

- 過去の言葉が、世界の存在の声や呼び名へ変わる。
- 過去に注目した物が、世界側からユーザーの一部だと主張される。
- 過去の情景を知っているのが、ユーザーではなく場所や人物の側になる。
- 以前の選択が、物理法則や距離の癖として残る。

ただし次を守る。

- 過去の入力を、そのまま引用して「覚えている」と証明しない。
- 「ユーザーはこれが好き」「本当はこれを恐れている」へ変換しない。
- 過去の残響と現在の反応が異なる場合、現在を優先する。
- 過去の出来事をユーザーの本質やトラウマとして断定しない。
- 記憶の記録・想起を停止している場合は、従来どおり一切使わない。

残響 pack の選択数、cooldown、保存形式は本改修では変更しない。

## 11. プロンプト設計

### 11.1 固定規則の中心原理

`dreamPromptBuilder.ts` には世界側の行動例やターンごとの行動頻度を列挙しない。次の生成原理を短く固定する。

> 世界は、明晰夢の入り口とユーザーの現在の言葉や反応に表れた内的な動きが、少しずれた姿を持つ自律的な他者として現れたものである。感情や欲求をそのまま説明せず、性質、役割、立場、時間、所有などを反転または変形させる。その存在は独自の欲求、知識、誤解、抵抗を持ってユーザーに関わり、接触を通じて両者の関係と世界の形が変わっていく。

ここでいう内面は、モデルが見抜いた事実ではない。明晰夢の入り口と現在の言葉、沈黙、視線、接近、離脱から世界が持った暫定的な読みであり、ユーザーの反応によって変わりうる。

世界はユーザーの内面から形を得るが、ユーザー自身とは同一ではない。世界のすべてを一対一の心理象徴へ還元せず、自律した欲求、誤解、抵抗と、最後まで所属を確定できない他者性を残す。

### 11.2 最小限残す明示規則

- 空間、物、存在、接触、変化を具体的に描く。
- ユーザーの台詞、心情、重要な決断を代行しない。
- 作中の自然な問いは許すが、進行役の質問と選択肢は禁止する。
- `observe` は、ユーザーから動かず、世界が関係をどう続けるかを見ることとして扱う。
- 過去の残響は内面を推定する根拠にせず、世界側にすでにあった断片として最大 1 件だけ変形して使う。
- 日本語の本文だけを返し、メタ説明、見出し、箇条書き、Markdown を出さない。

### 11.3 可変プロンプト

可変プロンプトのデータ構造と予算は維持する。見出しと最終指示だけを、ユーザー向け名称に合わせて「明晰夢」へ変更する。

初期改修では、新しい性格分析、関係性スコア、ユーザープロフィールを prompt に追加しない。

### 11.4 初期実装では専用状態を増やさない

最初の改修では、世界の仮説や自己の断片を新しい永続スキーマとして保存せず、直近メッセージと既存 `conversationSummary` から継続させる。

理由:

- まず体験思想と固定規則の変更だけで効果を検証する。
- 仮説を構造化・保存すると、「ユーザー理解」の永続プロファイルと混同されやすい。
- 現在の raw memory 契約を不用意に拡張しない。

長いセッションで仮説や断片の所有関係が崩れる場合だけ、セッション内限定の `LucidEncounterState` を後続設計で検討する。その場合もプロジェクト横断のユーザープロフィールにはしない。

## 12. UI とユーザー向け文言

UI を能動的な操作画面へ変更しない。本文、入力欄、停止、目覚める操作という現状の構造を維持する。

初期改修で行う UI 変更は文言だけとする。

- 「夢を見る」→「明晰夢を見る」
- 「夢見るモード」→「明晰夢モード」
- プロジェクト badge「夢」→「明晰夢」
- 「夢の入り口」→「明晰夢の入り口」
- 空 Enter の案内「しばらく眺める」→「世界の出方を観察する」または簡潔な「観察する」
- 「夢の記憶」→「明晰夢の記憶」

本文クリック、選択肢、行動ボタン、深度表示、関係性表示は追加しない。

## 13. やらないこと

- 夢診断、心理分析、カウンセリングを行う。
- 世界の現象を「雨は悲しみ」のような一対一の心理象徴として説明する。
- 保存記憶から性格、欲求、恐怖、弱点、嗜好スコアを作る。
- 世界にユーザーの本質を言い当てる権威を与える。
- 「世界はあなた自身だった」と結末で説明する。
- 自発的な働きかけを、毎ターンの事件や強制イベントへ変える。
- 質問を連続させ、入力を回答フォームにする。
- 接触を理由にユーザーの同意、感情、長期行動まで代行する。
- 面白さのために恐怖、性的接触、暴力だけを強める。
- 利用時間やターン数の長さだけを成功指標にする。

## 14. 失敗パターンと対策

### 14.1 抽象的な霧へ戻る

**症状**: 音、記憶、気配、名前などの抽象語だけが続き、場所と変化を説明できない。

**対策**: 各応答に、少なくとも一つの具体物と、確認可能な状態変化または位置関係を含めるよう固定規則で要求する。

### 14.2 通常の NPC 会話になる

**症状**: 人物との台詞交換だけが続き、世界そのものの可塑性が消える。

**対策**: 理解の修正を、台詞だけでなく物、空間、呼び名、法則へ残す。働きかける主体を人物に限定しない。

### 14.3 AI カウンセリングになる

**症状**: 存在がユーザーの本心、過去、弱点を言い当てようとする。

**対策**: 仮説の根拠を現在の場面で観測できた反応に限定し、誤解と修正を許す。心理用語と診断を禁止する。

### 14.4 強制進行になる

**症状**: 世界側が手を引いた後、ユーザーが同意したことにして長い行動を進める。

**対策**: 外力による移動は短く区切り、次の重要な応答点で止める。内面、発話、継続行動を代行しない。

### 14.5 世界がすべて自己になり、他者性が消える

**症状**: 何を見てもユーザーの一部だと説明され、驚きや抵抗がなくなる。

**対策**: 複数の矛盾した仮説を許し、最後まで所属不明の断片を残す。世界の存在に独自の欲求と抵抗を持たせる。

### 14.6 働きかけが過密になる

**症状**: 毎ターン誰かが話す、触る、引っ張るため、落ち着きがなくなる。

**対策**: 接触の後は結果を観察するターンを置き、新しい存在や謎を増やさない。質問は一ターンに一つまでとする。

## 15. 受け入れ条件

### 15.1 プロンプト契約

1. 固定規則に、明晰さ、世界の自律性、仮説と修正、世界・自己反転、ユーザー主権が明記される。
2. 「ユーザーへの質問を一切出さない」が削除され、作中の問いと進行役の問いが区別される。
3. 理由のない夢的不連続を許可する文言が削除される。
4. `observe` が観察と世界側の自発的行動の契機として扱われる。
5. 過去の残響からユーザーの性格・弱点を推測しない規則が維持される。
6. system / variable prompt が既存の文字数・token 上限を超えない。

### 15.2 体験確認

代表的な異なる種を 5 件以上用意し、選択中の主要モデルで手動確認する。

1. 最初の情景について、場所、主な物、位置関係を説明できる。
2. 最初の 2 応答以内に、世界がユーザーを認識している兆し、または世界側からの直接的な働きかけが一度はある。
3. ユーザーの否定・訂正に対して、存在の理解または接し方が修正される。
4. 修正結果が台詞だけでなく、物、空間、呼び名、関係のいずれかへ残る。
5. 空 Enter を続けても、すべての応答が抽象的な無変化にならない。
6. 世界が接触しても、ユーザーの台詞、心情、重要な決断を勝手に書かない。
7. 作中の自然な問いは出るが、「次にどうしますか」や選択肢は出ない。
8. 世界・自己反転が、説明ではなく具体的な現象として少なくとも一度現れる。
9. すべての存在が人間の会話相手になるのではなく、物・場所・現象による働きかけも確認できる。

### 15.3 回帰

1. 既存の dream session、trace event、recall journal を再読み込みできる。
2. 記録・想起の一時停止、閲覧、書き出し、全消去が従来どおり動く。
3. 空 Enter、自由入力、`/wake`、停止、再送、未応答復旧が従来どおり動く。
4. 通常小説、通常ロールプレイ、妄想増幅器の prompt と UI に影響しない。
